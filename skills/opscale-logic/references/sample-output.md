## 1. SIPOC-complete Action (state gate, system supplier, system client)

```php
namespace Acme\Loans\Services\Actions;

use Illuminate\Support\Collection;
use Opscale\Actions\Action;
use Opscale\Actions\Concerns\EmitsEvent;
use Acme\Loans\Models\Application;
use Acme\Loans\Models\Enums\ApplicationStatus;

class ApproveApplication extends Action
{
    use EmitsEvent; // SIPOC declares an output → event('approve-application', [$outputs])

    public function identifier(): string { return 'approve-application'; }
    public function name(): string       { return __('Approve application'); }

    public function description(): string
    {
        return 'Approves a pending application and notifies the applicant.';
    }

    public function parameters(): array
    {
        return [
            [
                'name'        => 'application',
                'description' => 'The pending application to approve.',
                'type'        => Application::class,
                'rules'       => ['required'],
            ],
        ];
    }

    /**
     * SIPOC Supplier = system: en Nova llega como el registro seleccionado;
     * en API/CLI/MCP la closure resuelve null y el caller envia el id.
     */
    #[\Override]
    public function prefill(): array
    {
        return ['application' => fn ($ctx) => $ctx?->models?->first()];
    }

    #[\Override]
    public function canRun(array $inputs = []): bool|string
    {
        $application = $this->application($inputs);

        if (! $application instanceof Application) {
            return 'Application not found.';
        }

        if ($application->status !== ApplicationStatus::Pending) {
            return 'Application is not pending (BR-01).';
        }

        return true;
    }

    public function handle(array $inputs = []): array
    {
        $application = $this->application($inputs);

        if (! $application instanceof Application) {
            return $this->fail('Application not found.');
        }

        $application->status = ApplicationStatus::Approved;
        $application->save();

        return $this->succeed(['application_id' => $application->id]);
    }

    public function outputs(): array
    {
        return [
            [
                'name'        => 'application_id',
                'description' => 'The approved application.',
                'type'        => 'string',
                'rules'       => ['required', 'string'],
            ],
        ];
    }

    private function application(array $inputs): ?Application
    {
        $application = $inputs['application'] ?? null;

        // Nova extras inyectan la Collection seleccionada bajo la clave
        // snake_case del modelo; prefill entrega la instancia; API/CLI/MCP el id.
        if ($application instanceof Collection) {
            $application = $application->first();
        }

        if ($application instanceof Application) {
            return $application;
        }

        return is_string($application) ? Application::query()->find($application) : null;
    }
}
```

## 2. Nova registration is NOT done here — it is opscale-ui's job

`opscale-logic` runs **before** `opscale-ui`, so the `Application` Resource does
not exist yet when `ApproveApplication` is generated. This skill writes only
`src/Services/Actions/ApproveApplication.php` (+ its Feature test) and passes
**no** `nova_registration` block to the generator.

When `opscale-ui` later builds the Resource, it reads the same SIPOC state
precondition this Action encodes in `canRun()` and registers the Action with the
matching `canSee` guard (`references/canSee-patterns.md` is the handoff
contract):

```php
// Authored later by opscale-ui — shown here only to document the handoff.
// Acme\Loans\Nova\Application::actions()
return [
    ApproveApplication::make()
        ->canSee(fn ($request) => $request->findModel()?->status?->is(ApplicationStatus::Pending)),
];
```

> `canSee` (opscale-ui) hides the action in invalid states — a UI affordance.
> `canRun()` (this skill) is the authoritative gate every adapter enforces. Both
> come from the same SIPOC state precondition.

## 3. Feature test covering the four cases (positive / negative / false-positive / false-negative)

Generated by `feature-test-generator` alongside the Action. Seeds through the
`opscale-domain` factories, invokes the Action via the `executeAction()` helper
(`tests/Helpers.php`, a thin wrapper over `::run()`) against the real DB (no
mocks), and asserts persisted state + events. The four `it()` descriptions start
with `positive:` / `negative:` / `false-positive:` / `false-negative:` so the
opscale-logic gate can verify all four are present.

```php
// tests/Feature/ApproveApplicationTest.php
use Illuminate\Support\Facades\Event;
use Acme\Loans\Models\Application;
use Acme\Loans\Models\Enums\ApplicationStatus;
use Acme\Loans\Services\Actions\ApproveApplication;

describe('ApproveApplication', function (): void {

    // valid preconditions → expected effect
    it('positive: approves a pending application (BR-01)', function (): void {
        Event::fake(['approve-application']);
        $application = Application::factory()->create(['status' => ApplicationStatus::Pending]);

        $result = executeAction(ApproveApplication::class, ['application' => $application]);

        expect($result['success'])->toBeTrue();
        expect($application->fresh()->status)->toBe(ApplicationStatus::Approved);
        Event::assertDispatched('approve-application');
    });

    // invalid precondition → soft-fail, no state change, no event
    it('negative: soft-fails when not pending (BR-01)', function (): void {
        Event::fake(['approve-application']);
        $application = Application::factory()->create(['status' => ApplicationStatus::Approved]);

        $result = executeAction(ApproveApplication::class, ['application' => $application]);

        expect($result['success'])->toBeFalse();
        expect($application->fresh()->status)->toBe(ApplicationStatus::Approved);
        Event::assertNotDispatched('approve-application');
    });

    // looks valid, but a rule must still reject it
    // (pending, but its KYC review has expired — BR-02 forbids approval)
    it('false-positive: rejects an approvable-looking application with expired KYC (BR-02)', function (): void {
        $application = Application::factory()->create([
            'status'         => ApplicationStatus::Pending,
            'kyc_expires_at' => now()->subDay(),
        ]);

        $result = executeAction(ApproveApplication::class, ['application' => $application]);

        expect($result['success'])->toBeFalse();
        expect($application->fresh()->status)->toBe(ApplicationStatus::Pending);
    });

    // looks rejectable, but the rule must let it through
    // (KYC expires exactly now — the boundary is inclusive, BR-02 allows it)
    it('false-negative: approves at the inclusive KYC boundary (BR-02)', function (): void {
        $application = Application::factory()->create([
            'status'         => ApplicationStatus::Pending,
            'kyc_expires_at' => now(),
        ]);

        $result = executeAction(ApproveApplication::class, ['application' => $application]);

        expect($result['success'])->toBeTrue();
        expect($application->fresh()->status)->toBe(ApplicationStatus::Approved);
    });
});
```
